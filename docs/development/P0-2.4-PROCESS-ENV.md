# P0-2.4: process.env — 外部环境适配能力

## 阶段目标
实现 TLL 的 `process.env`，让 TLL 程序能够读取真实宿主环境变量，并通过 Dogfooding 项目验证能力。

## 问题
TLL 之前只有 `process.argv` 和 `process.exit`，缺少读取环境变量的能力。一个 Agent 用 TLL 开发真实软件时，读取配置（如 API key、环境标识、路径）会立即撞墙。

## 实现

### Native Builtin
- `host/c/builtin.c`: 新增 builtin 122，遍历 C `environ` 全局变量，构建 TLL Map 返回。
- Windows 下环境变量名归一化为大写（因为 Windows env 大小写不敏感）。

### Compiler
- `compiler/codegen.tll`: 对 `process.env` 成员访问做特殊处理，直接发射 `OP_LOAD_BUILTIN 122` + `OP_CALL`，避免走通用 member get 路径。

### API
```tll
let env = process.env       // returns Map<string, string>
let path = env["PATH"]      // returns string or null
let missing = env["NOPE"]   // returns null
```

## Dogfooding 项目: envget
`tools/envget/main.tll` — 一个真实的命令行工具：
- 读取命令行参数（`process.argv`）
- 读取环境变量（`process.env`）
- 输出 `NAME=VALUE` 或 `NAME=<not set>`
- 全部找到 exit 0，有缺失 exit 1（`process.exit`）

覆盖能力：变量、函数、Array、Map、String、循环、条件、process.argv、process.env、process.exit。

## 测试系统升级
P0-2.4 同步升级了测试运行器，解决审计员指出的"PASS 只代表 exit code 0"问题：

### 新断言机制
1. **Exit code 断言**: 测试文件命名为 `exitN.tll`（如 `exit42.tll`）表示期望退出码 N。默认期望 0。
2. **Stdout 断言**: 同目录下存在 `<name>.expected.txt` 时，比较程序 stdout 与期望内容。

### 受影响文件
- `scripts/run-tests.bat` (Windows)
- `scripts/run-tests.sh` (Linux/macOS)

### 非零退出码回归测试
- `tests/regression/exit42.tll`: 调用 `process.exit(42)`，验证 Native launcher 得到正确退出码。

## 测试结果
29/29 全部通过：
- 15 acceptance tests
- 5 regression tests (含 exit42, test_env)
- 9 regression test directories (module/package 测试)

## 已知限制
- `process.env` 当前只读，不支持设置/删除环境变量。
- 每次访问 `process.env` 都会重新构建整个 Map，未做缓存。
- Windows 下 key 归一化为大写，与 Linux/macOS 的大小写敏感行为不同。
