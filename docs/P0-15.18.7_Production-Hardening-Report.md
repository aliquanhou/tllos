## 已知限制（NOT READY for Production）

### 1. 密码学签名 🔴 HIGH
- **状态**: SIMULATED
- **说明**: 当前 `signTransaction()` 使用 HMAC-SHA256(publicKey, message)，不是真实的非对称加密签名
- **影响**: 不能防止交易伪造，不能证明交易发送者身份
- **计划**: 未来阶段引入 Ed25519 / secp256k1
- **风险等级**: HIGH

### 2. 共识机制 🔴 HIGH
- **状态**: PARTIAL
- **说明**: 当前只有最长链规则的基础实现，没有完整的共识算法
- **缺失**: Chain Reorg、Heaviest Chain Selection、Orphan Block Pool、Fork Resolution、难度调整
- **影响**: 网络出现分叉时无法自动恢复一致
- **风险等级**: HIGH

### 3. 账户状态 / Nonce 🟡 MEDIUM
- **状态**: PARTIAL
- **说明**: Mempool 有 nonce 查询，但没有完整的账户状态管理
- **缺失**: 账户余额状态、Nonce 连续性验证、双花检测、Block 执行后状态更新
- **影响**: 不能防止双花，不能验证交易发送者有足够余额
- **风险等级**: MEDIUM

### 4. TCP 并发连接限制 🟡 MEDIUM
- **状态**: DESIGN LIMIT
- **说明**: `tcp.select()` 使用 `select()` API，`FD_SETSIZE=64`
- **行为**: 超过 64 个 fd 的连接被静默忽略（不会崩溃，但不会收到事件通知）
- **影响**: 单节点最多支持约 60 个并发连接
- **计划**: 未来迁移到 epoll/kqueue/IOCP
- **风险等级**: MEDIUM

### 5. 持久化 🟡 MEDIUM
- **状态**: MISSING
- **说明**: Blockchain 状态完全在内存中，节点重启后从 Genesis 开始
- **影响**: 节点重启后需要重新同步整个链，不能持久化状态
- **计划**: 未来引入 LevelDB / 文件持久化
- **风险等级**: MEDIUM

### 6. 自动重连 🟡 MEDIUM
- **状态**: PARTIAL
- **说明**: 有 `p2pReconnect()` API，但没有后台自动重连机制
- **行为**: 节点断线后需要外部触发重连，不会自动重连
- **影响**: 网络临时故障后节点不会自动恢复连接
- **风险等级**: MEDIUM

### 7. Windows TCC 构建 ⚪ LOW
- **状态**: UNVERIFIED
- **说明**: TCC 的 `stddef.h` 在 CI 环境中编译失败
- **当前状态**: CI 使用 MSVC `cl` 编译 Windows Runtime
- **影响**: TCC 编译的 Runtime 未经过 CI 验证
- **风险等级**: LOW（不影响 MSVC 构建）

### 8. 消息协议版本化 ⚪ LOW
- **状态**: MISSING
- **说明**: P2P 消息协议没有版本号，不支持协议协商
- **影响**: 不同版本节点之间可能不兼容
- **风险等级**: LOW

## 生产加固建议

### 高优先级（阻断生产部署）
1. **真实密码学签名**: 引入 Ed25519，替换 HMAC 模拟签名
2. **完整共识机制**: 实现 Chain Reorg、Orphan Pool、最长链选择
3. **账户状态管理**: 实现余额、Nonce、双花检测

### 中优先级（生产环境强烈建议）
4. **持久化**: 引入 LevelDB 或文件持久化
5. **TCP 并发升级**: 迁移到 epoll/kqueue/IOCP
6. **自动重连**: 后台自动重连机制
7. **结构化日志**: JSON 格式日志，便于运维监控
8. **指标导出**: Prometheus 格式指标

### 低优先级（长期改进）
9. **消息协议版本化**: 协议协商和版本兼容
10. **配置文件**: 节点配置文件（端口/peer list/difficulty）
11. **TCC 构建修复**: 修复 TCC CI 环境问题
12. **性能优化**: SHA256 C 原生加速、签名批处理

### Production Readiness 判定

**总体判定: NOT READY for Production**

TLL OS 当前适合作为:
- 编程语言/Runtime 能力验证平台
- 区块链技术原型和实验
- Agent 开发框架实验
- 教育和研究用途

不适合作为:
- 生产级区块链节点
- 金融交易系统
- 高并发生产服务

**达到 Production Ready 需要完成**:
1. 真实密码学签名（HIGH）
2. 完整共识机制（HIGH）
3. 账户状态管理（MEDIUM）
4. 持久化（MEDIUM）
5. TCP 并发升级（MEDIUM）
