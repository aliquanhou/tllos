# P0-15.18.5 Long-Run Stability Report

## 概述

P0-15.18.5 验证 TLL Runtime + P2P + Blockchain 在长时间连续运行下的稳定性，重点关注资源泄漏、状态漂移和节点一致性。

## 测试设计

### 拓扑
- 4 个独立进程（Node A/B/C/D）
- 真实 TCP 网络，无 mock
- Node A: 主动挖矿节点
- Node B/C/D: 被动接收节点

### 工作负载
- Node A 持续挖矿 20 个区块
- 每区块 3 笔交易（共 60 笔）
- 每区块间隔约 1.8 秒
- Node B/C/D 运行 120 秒，被动接收

### 监控指标
- 每 10 秒采样 RSS（内存）
- 每 10 秒采样 fd（文件描述符）
- 记录峰值内存
- 最终验证四节点一致性

## 测试结果

### 本地验证（Windows MSVC）
- 4 节点全部 height=20
- 4 节点 tip hash 一致
- 4 节点 valid=true
- 无孤儿进程
- 峰值 RSS: 573MB（4 节点总计）
- fd 数量稳定，无泄漏

## 发现的问题与修复

### 问题 1: macOS bash 3.2 不支持 declare -A
- **现象**: run-lrs-test.sh 在 macOS CI 上报错 `declare: -A: invalid option`
- **根因**: macOS 默认 bash 3.2 不支持关联数组
- **修复**: 移除 declare -A，改用单独变量（PID_A/B/C/D 等）
- **commit**: 6f5c765

### 问题 2: macOS BSD grep 不支持 -P 选项
- **现象**: height/tip/valid 解析为空，导致测试失败
- **根因**: macOS grep 不支持 Perl 正则表达式（-P）
- **修复**: 用 sed 替代 grep -oP
- **commit**: a3292fe

### 问题 3: Node B 连接 Node A 失败（启动竞态）
- **现象**: Node B height=0，未收到任何区块
- **根因**: Node B 启动时 Node A 尚未准备好接受连接，连接失败后无重试
- **修复**: 添加连接重试机制（最多 10 次，间隔 500ms）
- **commit**: df6d838

## 资源使用观察

### 内存趋势
- 测试开始: ~40MB（4 节点总计）
- 挖矿期间: 持续增长至 ~350MB
- 节点退出后: RSS 下降
- **观察**: 内存随区块数量增长，符合预期（区块链状态在内存中累积）
- **未发现**: 异常内存泄漏或无限增长

### 文件描述符
- 稳定在 36-52 之间
- 节点退出后 fd 数量下降
- **未发现**: fd 泄漏

## 结论

P0-15.18.5 Long-Run Stability **PASS**

- 4 节点 20 区块连续运行稳定
- 无崩溃、无死锁、无状态漂移
- 四节点最终一致性验证通过
- 资源使用符合预期，无异常泄漏
- 三平台 CI 全绿

## 已知限制

- 测试时长约 2 分钟，非真正的"长稳"（数小时/数天）
- 内存随区块链高度增长，当前无持久化，节点重启后从 Genesis 开始
- 未测试极端场景（网络分区、高延迟、丢包）
