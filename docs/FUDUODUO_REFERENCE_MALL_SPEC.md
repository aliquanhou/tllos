## 一、系统概览

### 1.1 技术栈

| 层级 | 技术 |
|------|------|
| 后端框架 | ThinkPHP 6.0 + PHP 8.0 |
| 数据库 | MySQL / MariaDB (表前缀 `ls_`) |
| 缓存 | Redis (Session、Token、数据缓存) |
| 前端架构 | 四端分离 (PC / Mobile / Admin / Shop) |
| 自定义架构 | tllos (Controller + Logic + Validate 三层) |
| Web服务器 | Nginx + PHP-FPM |
| SSL | Let's Encrypt |

### 1.2 系统规模

| 指标 | 数量 |
|------|------|
| 数据库表 | ~130 张 |
| API 路由 | 132+ 个 |
| Admin 控制器 | 12 个 |
| 前台 API 控制器 | 5 个 |
| 定时任务 | 12 个 |
| 业务逻辑层 (Logic) | 30+ 个 |
| 前端入口 | 4 个 (pc / mobile / admin / shop) |

### 1.3 四端架构

```
┌─────────────────────────────────────────────────────────┐
│                        Fuduoduo 商城                       │
├──────────┬──────────┬──────────────┬────────────────────┤
│  PC 端   │ 移动端    │  管理后台     │   商家后台          │
│  /pc/    │ /mobile/ │  /admin/     │   /shop/           │
│ 商品浏览  │ 商品浏览  │  平台运营     │   店铺管理          │
│ 购物车    │ 购物车    │  商品审核     │   商品管理          │
│ 下单支付  │ 下单支付  │  订单管理     │   订单处理          │
│ 用户中心  │ 用户中心  │  用户管理     │   财务结算          │
└──────────┴──────────┴──────────────┴────────────────────┘
```

**数据表**: `ls_user_address`

**功能**:

### 2.10 订单管理

**数据表**:
- `ls_mall_order` - 订单主表
- `ls_mall_order_goods` - 订单商品表
- `ls_mall_order_log` - 订单操作日志
- `ls_mall_order_create` - 订单创建记录表

**订单状态机**:
```
待付款 (0)
  ├─ 支付成功 → 待发货 (1)
  │     ├─ 发货 → 待收货 (2)
  │     │     ├─ 确认收货 → 已完成 (3)
  │     │     └─ 超时自动确认 → 已完成 (3)
  │     └─ 申请售后 → 售后中
  ├─ 取消订单 → 已取消 (4)
  └─ 超时未支付 → 已取消 (4) [定时任务自动关闭]
```

**功能**:
- 订单列表（按状态筛选：全部/待付款/待发货/待收货/已完成/已取消）
- 订单详情
- 取消订单（待付款状态）
- 确认收货（待收货状态）
- 申请售后（已完成/待收货）
- 查看物流
- 订单商品评价入口
- 订单金额明细
- 订单状态时间线

### 2.11 支付

**数据表**:
- `ls_mall_pay` - 支付记录表
- `ls_mall_pay_scene` - 支付场景配置

**支付渠道**:
- 微信支付（JSAPI / Native / H5）
- 支付宝（PC / H5）
- 余额支付

**功能**:
- 支付下单（创建支付单）
- 调起支付（微信/支付宝）
- 支付回调（异步通知验签）
- 支付结果查询
- 支付成功后更新订单状态
- 重复支付防护（同一订单不能重复支付）
- 支付金额校验（防止篡改）
- 支付幂等性

### 2.12 退款与售后

**数据表**:
- `ls_mall_order_after_sale` - 售后申请表
- `ls_mall_order_after_sale_log` - 售后操作日志
- `ls_mall_refund` - 退款记录表
- `ls_mall_refund_log` - 退款操作日志

**售后流程**:
```
用户申请售后
  ├─ 仅退款 → 商家审核 → 退款到账
  └─ 退货退款 → 商家审核 → 用户退货 → 商家收货 → 退款到账
```

**功能**:
- 售后申请（选择商品、售后类型、原因、凭证图片）
- 售后列表
- 售后详情
- 撤销售后申请
- 退货物流填写
- 退款进度查询
- 售后状态：待审核、已通过、已拒绝、退货中、已完成

### 2.13 会员与积分

## 四、业务流程审计

### 4.1 核心购买流程

```
注册 → 登录 → 浏览商品 → 搜索 → 选择SKU → 加入购物车
  → 修改数量 → 优惠券 → 结算 → 选择地址 → 创建订单
  → 支付 → 支付回调 → 库存扣减 → 订单状态变更(待发货)
  → 商家发货 → 物流 → 用户确认收货 → 订单完成
  → 评价 → 积分奖励
```

### 4.2 订单状态机

| 状态 | 状态值 | 说明 | 可执行操作 |
|------|--------|------|-----------|
| 待付款 | 0 | 订单已创建，未支付 | 支付、取消 |
| 待发货 | 1 | 已支付，待商家发货 | 发货、申请售后 |
| 待收货 | 2 | 已发货，待用户确认 | 确认收货、申请售后、查看物流 |
| 已完成 | 3 | 交易完成 | 评价、申请售后 |
| 已取消 | 4 | 订单已取消 | 查看详情、重新购买 |

### 4.3 支付流程

```
用户提交订单 → 创建支付单 → 调起支付(微信/支付宝)
  → 用户支付 → 支付平台异步回调 → 验签 → 校验金额
  → 更新支付单状态 → 更新订单状态(待发货) → 扣减库存
  → 记录订单日志 → 发送通知
```

**支付幂等性**:
- 同一订单只能有一个有效支付单
- 回调重复通知时，校验支付单状态，已成功则直接返回成功
- 支付金额与订单金额校验，防止篡改

### 4.4 退款流程

```
用户申请售后 → 选择售后类型(仅退款/退货退款)
  → 填写原因、凭证 → 提交申请 → 商家审核
  → 审核通过 → 仅退款: 直接退款到账
              → 退货退款: 用户填写退货物流 → 商家收货确认 → 退款到账
  → 审核拒绝 → 用户可重新申请或申诉
  → 退款到账 → 更新售后状态 → 记录退款日志 → 库存回滚(退货退款)
```

### 4.5 库存逻辑

**库存扣减时机**: 支付成功后扣减（非下单时扣减）

**库存回滚时机**:
- 订单取消（待付款状态）
- 订单超时自动关闭
- 售后退货退款完成

**并发控制**:
- 数据库事务
- 库存扣减使用 `UPDATE ... SET stock = stock - ? WHERE id = ? AND stock >= ?`
- 防止超卖

### 4.6 异常流程

| 异常场景 | 处理方式 |
|----------|---------|
| 库存不足 | 下单时提示，支付时再次校验 |
| 重复提交 | 前端按钮禁用 + 后端订单号幂等 |
| 重复支付 | 支付单状态校验，已支付则返回原支付单 |
| 支付失败 | 订单保持待付款，用户可重新支付 |
| 取消订单 | 待付款状态可取消，已支付需走售后 |
| 超时订单 | 定时任务自动关闭未支付订单 |
| 并发下单 | 数据库事务 + 乐观锁 |
| 并发扣库存 | `WHERE stock >= ?` 条件更新 |
| 未登录访问 | 重定向到登录页，登录后回跳 |
| 权限不足 | 返回 403 / 友好提示 |
| Session 失效 | 重新登录 |
| 非法参数 | 参数校验 + 友好错误提示 |
| 重放请求 | 支付回调验签 + 幂等性 |
