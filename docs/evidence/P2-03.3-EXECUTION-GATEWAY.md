## 2. Phase 1: Execution Gateway Design ✅

**新增文件：**
- `tllos/agent_runtime/gateway/execution_gateway.md` — Gateway 说明
- `tllos/agent_runtime/gateway/gateway_request.json` — Gateway 请求格式
- `tllos/agent_runtime/gateway/gateway_response.json` — Gateway 响应格式

**流程：**
```
Agent → Task Contract → Capability Check → Permission Check → Execution Gateway → Runtime Adapter → Evidence
```

**Gateway 规则：**
- 所有执行请求必须经过 Gateway
- 无 permission_id 的请求直接 REJECT
- 无 evidence_required 的请求直接 REJECT
- permission state != approved 的请求直接 REJECT
- action 超出 task scope 的请求直接 REJECT

## 3. Phase 2: Runtime Adapter Interface ✅

**新增文件：**
- `tllos/agent_runtime/adapter/runtime_adapter.md` — Adapter 接口说明
- `tllos/agent_runtime/adapter/runtime_request.json` — Runtime 请求格式
- `tllos/agent_runtime/adapter/runtime_result.json` — Runtime 结果格式

**设计原则：**
- 隔离：Agent Runtime 不直接访问 Runtime Core
- 边界：所有 Runtime 调用必须经过 Adapter
- 可替换：未来可以替换不同的 Runtime 后端
- 可测试：Adapter 可以 mock，不依赖真实 Runtime

**禁止：**
- ❌ 调用 vm.c
- ❌ 修改 Runtime Core
- ❌ 直接访问 coroutine
- ❌ 直接访问 scheduler
