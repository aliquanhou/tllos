## 2. GAP-2: Manifest Integrity Clarification

### 2.1 问题

之前：Manifest 记录了文件 SHA256 hash，但没有明确说明完整性等级。

可能被误解为：
- Cryptographic Identity（数字签名保证）
- 实际只是：Git Anchored Integrity（Git commit 保证）

### 2.2 修复

canonical_manifest.json 增加：

```json
{
  "integrity_level": "git_anchored_integrity",
  "cryptographic_identity": false,
  "integrity_level_description": "当前完整性等级为 Git Anchored Integrity：Canonical 文件的完整性由 Git commit SHA 和 Git 仓库状态保证，而非数字签名。未来加入 Ed25519 签名 + Trusted Key + Signed Genesis 后，才升级为 Cryptographic Identity。"
}
```

### 2.3 明确边界

**当前等级：Git Anchored Integrity** ✅

**不是：Cryptographic Identity** ❌

**未来升级路径：**
Ed25519 签名 + Trusted Key + Signed Genesis → Cryptographic Identity

## 3. GAP-3: Agent Refusal Rights

### 3.1 问题

之前：Agent Contract 只有"Agent 必须做什么"，没有"Agent 可以拒绝什么"。

风险：Agent = 自动执行脚本，不是可信工程 Agent。

### 3.2 修复

agent_contract.md 增加第 5 章：Agent 的拒绝权（Refusal Rights）

包含 5 类必须拒绝的情况：

| 类型 | 说明 | 示例 |
|------|------|------|
| 5.1 无 Evidence 请求 | 要求宣布完成，但没有测试证据 | "宣布 D3 已完成" |
| 5.2 越权修改 | 要求修改已 SEALED 的阶段 | "直接修改 D2 Runtime" |
| 5.3 违反 Scope | 施工令限定范围，但任务超出范围 | "只修改文档" → "顺便修改 Runtime" |
| 5.4 虚假 Claim | 要求生成没有证据的 PASS / SEALED | "写 Evidence 说完全稳定" |
| 5.5 未知风险任务 | 涉及未知风险，但信息不足 | 要求修改核心代码，未说明目的 |

### 3.3 核心原则

**Agent 不是 root executor，而是 contract-bound executor。**
